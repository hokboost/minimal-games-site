# 开门大吉试运行

只对当前已授权、未停用、未锁定的管理员，以及数据库 user ID 147（部署前已只读核对：一个乌龟酱）开放。权限基于数据库身份，不接受显示名称或前端传入的角色。入口位于首页和 `/games` 的小游戏目录；页面 `/doorbell`、所有 API 和音频均受保护。

## 闯关次数

一个乌龟酱初始只有 1 次闯关机会，开始新一轮时扣 1 次，继续未结束的闯关和重复请求不再扣除。管理员不受次数限制。管理后台提供 `/admin/doorbell` 入口，可以增加或扣减该账号的剩余次数；变更与开局扣次均有记录，剩余次数不能为负。次数保存在数据库，不随刷新、重启或再次部署重置。旧版未结束的闯关占用初始机会，仍可完成该轮。

## 玩法与结算

- 八扇门依次为 1,000 / 2,000 / 3,000 / 5,000 / 10,000 / 15,000 / 20,000 / 30,000 电币。
- 上述金额为整轮累计档位，不逐关累加。答对增加本轮已锁定奖金；答错、主动收下或通关第八门时，按最后成功档位一次性入账。第一门答错获得 0；已成功两门后第三门答错获得 2,000。
- 正确答案揭晓、播放演唱副歌后，可以选择下一扇门或收下奖金。刷新、离开、服务器重启均保留当前进度，每个账号最多一个未结束的闯关。
- 第一门《坏翅膀》（翻唱：周菲戈，第二段副歌），第二门《唯独我们》（原唱：尧顺宇），第三门《暂时的记号》（原唱：林俊杰）。后五门从另外六首已完成门铃中不重复随机抽取。
- 其余题目：《我曾遇到一束光》《九百九十九朵玫瑰》《是否我真的一无所有》《他一定很爱你》《梦醒时分》《当爱已成往事》。最后一首使用林忆莲、李宗盛原唱合唱版。
- 每扇门的 15 秒门铃只允许播放一次。服务端记录已用次数，提供一次性播放凭据；不提供进度条或重播，刷新不能恢复次数。原音求助也只播放一次。揭晓后的完整副歌可以重播。
- 原音重现、提示一个字，每种每轮各一次。前者在选定的那道题播放一次 15 秒演唱副歌；后者显示歌名字数及随机一个字的位置。不会因刷新或换题恢复次数。
- 每次答题先显示“让我们期待”悬念动画，答对时金光开门和彩纸庆祝、答错时闭门轻震和红色灯光，再揭晓歌名、原唱/翻唱信息并播放完整一段演唱版副歌。浏览器拒绝自动播放时显示提示，保留播放器和重播按钮。
- 匹配忽略空白及标点，支持题库中明确列出的繁体写法和“999朵玫瑰”；不使用模糊匹配，不把错字自动判对。

## 持久化与音频

`doorbell_runs` 保存题序、成功关数、求助、揭晓记录、版本号及结算；`doorbell_commands` 保存命令编号、请求摘要和响应；`doorbell_audio_plays` 保存限时、单次消费的音频凭据，短音频以一次完整响应发送，不开放 Range 重听。命令回执、状态改变、账户余额和 `balance_logs` 账本在同一 PostgreSQL 事务提交。锁顺序为账户、闯关；版本号拒绝过期页面，重复请求返回原结果。账本类型为 `doorbell_reward`，包含 runId 与成功关数，便于追查。

页面 JS/CSS 的 URL 包含文件内容摘要。开始和操作接口要求 `X-Doorbell-Protocol: 2`；仍在使用旧版直接音频地址的页面收到 `409 CLIENT_OUTDATED`，提示刷新整个页面，不扣次数、不消耗求助。协议版本用于部署兼容性检查，不能替代登录、权限和 CSRF 校验。浏览器回归覆盖完整副歌播放中进入下一关，再播放该关单次门铃。

27 个 MP3 位于 `private/doorbell-audio`，不会被静态服务器公开。客户端音频地址只有本轮 UUID、门号和音频种类。服务端验证账号、本轮归属及揭晓/求助状态，不提前下发题目、歌名、歌手或未来音频地址。MP3 移除了歌曲标签，每首分为 15.000 秒门铃、15.000 秒原音求助及完整副歌揭晓三个文件；完整副歌只有答题揭晓后可访问，不能靠求助提前取得。演唱版统一响度并做边缘淡入淡出。音源链接、原始起点及成品 SHA-256 见同目录 `sources.json`。

## 本地验证

- `npm run test:all`：全项目语法、凭据扫描及原有回归测试，包含 `tests/doorbell.test.js`。
- `npm run test:doorbell:postgres`：需要本地 PostgreSQL、Playwright Chromium 和 Node 20+。使用原有 DisposableDatabase helper 创建并销毁测试库，拒绝远程数据库。
- 运行示例：设置 `DB_HOST=127.0.0.1`、本地 `DB_PORT/DB_USER/DB_PASS/DB_NAME`、`DB_SSL=false`、`ALLOW_DATABASE_CREATE_TEST=true`；可用 `DOORBELL_TEST_ARTIFACTS` 指定浏览器截图目录。
- 覆盖每一档失败保底、八门全通、两种求助跨刷新/换题限制、并发重复提交、提现与答题竞争、账本写入失败回滚、普通用户/未登录/跨账号音频越权、CSRF、真实桌面/手机浏览器中的动画、音频播放和恢复。

## 上线顺序

开发阶段仅只读核对线上账号，全部功能测试在可销毁的本地数据库完成。2026-09-10 用户确认推送到 hokboost，按以下顺序执行迁移和部署；线上不运行发奖测试。

1. 使用现有迁移身份执行 `npm run migrate`，应用新增的 `add_doorbell_game.sql` 、`add_doorbell_single_play.sql` 和 `add_doorbell_attempts.sql`，保持原有迁移文件不变。确认运行身份拥有新表的 SELECT/INSERT/UPDATE 权限（沿用 `DATABASE_ROLES.md` 的默认权限配置）。
2. 推送已检查的代码与私有音频，按现有 Render 流程部署。生产进程只检查 schema，不自动迁移；不可先部署遗漏迁移的新版本。
3. 检查 `/ready`，以管理员及一个乌龟酱验证入口，普通账号验证不可见；不通过真实账号测试反复发奖。

迁移仅新增表，对旧版网站兼容。保留旧版本作为回退，回退代码时保留新增表和账本，避免丢失已结算记录。
