# 游戏经济参数与 RTP 门禁

权威参数位于 `domain/games/configuration.js`，计算器位于
`domain/games/economics.js`。本文只解释当前策略，不能作为第二份运行时配置。

## 策略

- 可兑换随机玩法的理论 RTP 必须位于闭区间 98%–99%。
- 规划中心值是 98.5%，99% 是硬上限，不是调参目标。
- 所有权重使用百万分整数；结算金额保持整数。
- 修改参数后，注册表加载和测试必须同时通过，否则服务拒绝启动/合并。
- Quiz 是每日返还封顶的技能玩法，不套用固定概率 RTP。

## 策略型玩法为什么有两种结果

Flip 和 Stone 必须同时回答两个不同问题：

1. 玩家为了最大化期望净利润会采用什么策略？
2. 哪个策略的 `期望返还 / 期望总成本` 比值最高？

两者不一定相同，只检查第一个会漏掉接近无限重试的高比率策略。Flip 穷举
64 个停止/继续策略；Stone 用策略迭代精确求解状态转移，再用 Dinkelbach
迭代求最大比率。

边界回归测试故意锁住：Flip 第三次成本 184 会超过 99%，必须至少为 185；
Stone 第 4 档替换成本 353 会超过 99%，必须至少为 354。不要删除这些
“只差 1”的失败用例。
